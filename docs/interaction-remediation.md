# KNS 1.2.0 交互整改说明

依据《KNS 管理页交互整改规格书 UX 1.0》，本次按 P0/P1 范围调整既有 Komari 插件，没有增加独立服务、常驻进程或新框架。

## 已实现

- 首次初始化改为页面内三步引导；未初始化可只读浏览。服务端仍拒绝未初始化写操作。初始化同步探针并记录基线后创建默认订阅；重复提交不会再创建默认令牌。
- 新安装的新探针自动部署默认关闭；启用必须明确确认 root 安装影响。默认模板仅用于后续新探针，存量 Schema 1 自动部署设置和其他业务数据经迁移保留。
- 部署拆为选探针、协议与网络、逐机预览三步。离线/未授权目标显示阻断原因；批次 API 按机器返回结果并通过稳定批次 ID 复用任务。任务状态不把“已受理”显示为“已安装”，仅对后端判定可安全重试的单一失败 Job 显示重试。
- 节点行分别显示远端运行状态、健康检测证据和发布意图。TCP/TLS 可达不会标成“代理协议可用”；发布开关注明仍受订阅筛选约束。已支持的节点显示只改 KNS 名称的独立入口。
- 将管理页原生 prompt/confirm 流程换成统一业务对话框。卸载预览由服务端生成版本摘要；卸载请求必须回传匹配版本，服务端再次检查预览完整性、五分钟有效期和当前登记状态。
- 一次性订阅链接按实际格式显示并提供单链接复制、失败回退选中和本地保存。原生输出与 SubConverter 外部输出分组，外部组提示订阅 URI 与节点凭据会发送到所配置的服务。链接仅保留在当前页面内存；页面卸载会清除。默认新建格式为 URI 与 Mihomo 完整配置，其他已有格式仍保留。
- 探针行提供“查看节点”入口；节点页显示可清除的来源探针筛选标签，后台刷新保留当前筛选。
- 编辑草稿期间后台刷新不重绘页面；管理写入携带 `expectedRevision`，冲突返回新旧 revision 并保留浏览器输入。请求超时显示“结果待确认”；批次会先用相同 batch ID 查询既有 Job，避免盲目新建。
- 备份导入先解密检查范围和密钥兼容性；恢复与导入要求输入“恢复”、校验 revision、拒绝活动远程任务，并使用进程内维护锁与本地回滚副本。

## API 与数据兼容

| 变更 | 接口/字段 | 兼容处理 |
| --- | --- | --- |
| 首次配置和新探针授权 | `setup.complete`、`settings.defaults.update`、`autoProvision.retry` | 仅 Schema 2 首次安装走新引导；Schema 1 旧安装按既存状态处理 |
| 多机批次与有限重试 | `install.batch`、`job.retry`、`batchId`、`retrySpec` | 每机器持有幂等键；同键重试复用已建任务、异键冲突、禁止重试任务链式重试；敏感回调信息不进入公开 Job，`retrySpec` 不从状态 API 返回 |
| 卸载预览核验 | `instance.status`、`uninstall.previewVersion` | 预览绑定目标、资源清单与核查时间；服务端拒绝缺失、过期或不匹配的版本 |
| 并发编辑 | 可选 `expectedRevision` | 旧 API 调用继续可用；管理页写操作附 revision，冲突不覆盖草稿 |
| 备份检查与维护 | `backup.inspect`、`backup.restore.preview`、`backup.restore`、`/admin/import` | 原有加密包格式不变；旧导入调用须补确认短语，恢复前重新检查活动任务 |
| Schema 迁移 | Schema 1 → 2 | 保留机器、节点、订阅、令牌、任务、地址与审计；缺少历史自动部署字段时默认关闭；已配置旧安装跳过新手门禁 |

## 本地验证与边界

自动测试、运行环境、40 条规格验收用例和已执行项见 [UX 验收记录](ux-acceptance-t40.md) 与 [验收报告](acceptance-report.md)。本地 mock 不代表 Komari/Agent 真机结果。当前没有可用于本轮的脱敏 Komari 浏览器会话或授权测试 Agent，因此不提交伪造截图/录屏；对应 UI、响应式、回调、客户端导入和卸载真机项目均标为未执行或部分执行。

回退必须保留 KNS 数据目录。Schema 2 不能由旧版插件直接读取；回退旧包前需恢复与该旧包匹配的 state/key 备份。具体步骤见 [回滚演练](rollback-drill.md)。
